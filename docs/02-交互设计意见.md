# IconGems 交互设计意见 —— 对《产品规划 V2》的响应

> 角色：交互设计师 ｜ 输入：docs/01-产品规划.md + 现网走查（2026-10-24）
> 结论先行：**规划方向同意**。自托管（P0）不只是技术迁移，它会改变用户对「下载」的全部心智——用户从此可以信任每一次点击都在本站完成。交互层要围绕这个心智重做三件事：**信息架构（三品类）、搜索（统一入口）、交付（下载/批量）**。以下按优先级给出意见，每条含「现状问题 → 交互改法 → 验收点」。

---

## A. 随 P0 必须落地的交互（与自托管同版本上线）

### A1. 「本站直链」信任标识 ⭐ 新增

- **现状**：用户无法区分哪些文件来自本站、哪些会跳出（插画外链时期遗留心智）。
- **改法**：所有可下载资产统一盖「⌂ 本站直链」微徽标（tooltip：文件来自 icongems.kuige.me，永久有效）；详情弹窗下载按钮旁显示实际文件格式与尺寸（如 `WebP · 1024px`），不再出现任何第三域名。插画外链卡片（过渡期）则明确标「外站 ↗」。
- **验收点**：任意详情弹窗内不出现 api.iconify.design / cdn.ipaslogo.com 字样；徽标有 tooltip 且双语。

### A2. 图标搜索的本地化反馈与降级

- **现状**：搜索依赖远端 API，加载中文案是「实时 · api.iconify.design」；失败只有重试按钮。
- **改法**：
  - 本地索引加载完成前，搜索框 placeholder 显示「索引载入中…」且输入可用（排队，就绪后自动执行）；
  - 结果从「远端返回」改为「本地命中」，`fstatus` 文案改为「本站 29 库 · N 结果 · ~x ms」，把「快」变成可感知的卖点；
  - **空结果不再死胡同**：给出 ①拼写建议（索引模糊匹配）②热门分类 chips ③「用英文试试」提示（中文词→内置中英映射表）；
  - 保留错误重试态（本地索引 fetch 失败时），文案指引用户刷新。
- **验收点**：空结果页有 ≥2 条出路；索引未就绪时输入不丢、不报错。

### A3. 下载交付流统一（三品类同一套肌肉记忆）

- **现状**：图标弹窗（m*）功能多但格式/尺寸混在按钮组；吉祥物弹窗（mm*）是另一套按钮；插画无下载。
- **改法**：定义统一「交付区」组件，所有品类详情弹窗共用同一布局：
  - 主按钮 = 最常用动作（图标：复制 SVG；吉祥物：下载 WebP 1024px；插画：下载 ZIP）；
  - 次级 = 格式×尺寸矩阵（图标：SVG/PNG(16/32/64/128/256/512)；吉祥物：WebP/PNG）；
  - 复制类动作（SVG/React/Vue/HTML/CSS/URL）收进「复制代码」下拉，减少按钮噪音；
  - 下载成功 = 按钮 1.5s 变绿勾（沿用现有 copy 绿勾模式，体验已验证 ✅）。
- **验收点**：三品类弹窗交付区结构一致；常用动作 ≤1 次点击；任何格式下载 3s 内有反馈（开始或完成）。

### A4. 批量：从「过滤即打包」升级为「勾选 + 托盘」

- **现状**：ZIP 打包当前过滤结果全集（zipCurrent），用户无法只挑 8 个。
- **改法**：
  - 网格进入「选择模式」（顶部按钮 + 快捷键 `S`）：tile 出现勾选框，点选/框选；
  - 已选资产进入**底部常驻托盘**（`已选 8 项 · 全部下载 ZIP · 清空`），跨品类可混选（图标+mascot 一起打包）；
  - 保留「打包当前结果」入口为托盘内次级按钮。
- **验收点**：勾选 3 个图标 + 2 个 mascot → 一个 ZIP 内 5 个文件；托盘在滚动时常驻、可收起。

## B. 信息架构：双 tab → 三品类

### B1. 主导航重构

- **现状**：顶层只有 Mascot Logos ↔ Icon Search 两个 tab；「插画」藏在页尾链接区，与「一站式」定位不符。
- **改法**：顶栏一级导航改为三品类 **图标 Icons ｜ 头像·IP Avatars ｜ 插画 Illustrations**（P0 插画为「精选外链+筹备中」，P1 变实品类）；现 mascot tab 改名「头像·IP」（用户语言里这批资产 = 头像/IP 形象，"Mascot Logos" 是开发者语言）。
- **URL 保持** `?tab=icons|avatars|illus` 查询参数方案（GitHub Pages 无服务端路由，不用路径式，避免 404）。
- **验收点**：三 tab 双语可直达、可分享链接还原状态；旧 `?tab=icons` 链接不失效。

### B2. 全局统一搜索

- **现状**：两个 tab 各自一个搜索框（finder / mascots 内），词不互通。
- **改法**：hero 区保留**一个全局搜索框**，结果页内用「分组 tab：全部/图标/头像/插画」呈现（全部 = 按品类分节，各显前 24 个 + 「查看全部 N」）；搜索框支持 ↓↑+Enter 键盘选联想词；记录最近 5 个搜索词（本地）。
- **验收点**：一次输入三品类都有出路；联想延迟 <100ms（本地索引天然满足）。

### B3. 首屏（hero）改造

- **现状**：hero 有双 tab 切换块（heroIpas/heroIcons）。
- **改法**：hero 收敛为「一个搜索框 + 三品类直达卡（各带实时资产数：109,813 图标 / 3,448 头像 / N 插画）+ 一行最新上架」；删除 tab 切换块，减少一次点击。
- **验收点**：首屏不滚动即可搜索并看到三品类入口。

## C. 浏览与状态体验

### C1. 分类 chips 收纳

- **现状**：mascot 分类 chips（catchips）数量多，占两行以上。
- **改法**：首行显示「全部 + 前 8 个高频分类 + …更多」；展开为网格面板；选中项回填首行。图标库 chips（libchips）同规则。
- **验收点**：折叠态 chips 占 ≤1 行；展开/收起有 aria-expanded。

### C2. 长列表性能与滚动

- **现状**：renderGrid 一次性渲染全部命中（大集合浏览时上千 tile）。
- **改法**：虚拟滚动或分页加载（首屏 60，滚动增量 60 + IntersectionObserver）；网格容器高度锁定避免跳动。
- **验收点**：浏览 19,876 枚的 Fluent 集合，首次可交互 <1.5s，滚动无可感知卡顿。

### C3. 状态四件套补全

- **现状**：空态、错误态已有雏形（fempty/ferr），加载中缺骨架屏。
- **改法**：网格区统一骨架屏（12–16 个 tile 占位 shimmer）；图片 tile 保留懒加载+占位底色；错误态文案区分「索引加载失败（刷新）」与「该资产缺失（反馈给我们）」。
- **验收点**：弱网（Fast 3G）下无白屏；prefers-reduced-motion 时骨架屏停止动画（现有支持保留）。

### C4. 键盘与焦点

- **现状**：弹窗内已有 ←→ 切换（navModal/navMModal）✅。
- **改法**：补 `/` 聚焦搜索、`Esc` 关闭弹窗/收起面板、`Enter` 打开焦点 tile、焦点圈（focus-visible）全组件覆盖；弹窗打开时焦点陷阱，关闭后焦点还原到触发的 tile。
- **验收点**：纯键盘可完成「搜索→浏览→打开→下载」全流程。

---

## D. 移动端专项（≤640px）

1. **底部动作栏**：详情改为底部抽屉（bottom sheet）而非居中弹窗；交付区按钮吸底，拇指可达；
2. **批量托盘**与底部动作栏复用同一位置，避免双层悬浮；
3. **顶栏收纳**：三品类 tab 收进底部固定 tab bar（图标/头像/插画/更多），顶栏只留 logo+主题+语言；
4. 大图查看支持双指缩放。
- **验收点**：390px 宽下单手可完成一次下载；无横向滚动条。

---

## E. 反馈与微文案

- toast 体系统一（复制/下载/出错共用同一位置与时长），替代零散按钮内变化（copy 绿勾保留在按钮内，作为「就地确认」，与 toast 不冲突：就地确认成功类、toast 用于过程类如「ZIP 生成中…」）；
- 全部微文案双语同步审校（现 i18n 键已完备，随新功能补 zh/en 两套）；
- 数字本地化：`109,813` 在中文环境显示 `10.9 万`（更符合中文用户感知）。
